# فایل‌های خروجی ساخت (Build Artifacts)

## مقدمه

تمام فایل‌های تولیدشده توسط ابزارهای پروژه در پوشه `build/` قرار می‌گیرند.

این پوشه به‌صورت خودکار ایجاد می‌شود و شامل گزارش‌ها، فایل‌های حاصل از سنتز، فایل‌های موج شبیه‌سازی و سایر فایل‌های تولیدشده است. هیچ‌یک از فایل‌های این پوشه نباید به‌صورت دستی ویرایش شوند.

---

# ساختار پوشه

```text
build/
├── logs/
├── synth/
├── waves/
└── work/
```

---

# پوشه logs/

این پوشه شامل فایل‌های گزارش (Log) تولیدشده توسط اسکریپت‌های پروژه است.

نمونه فایل‌ها:

```text
lint_20260728_214851.log
sim_20260728_214902.log
synth_20260728_215010.log
```

این گزارش‌ها برای بررسی خطاها و اشکال‌زدایی فرآیند تحلیل، شبیه‌سازی و سنتز استفاده می‌شوند.

توسط اسکریپت‌های زیر تولید می‌شوند:

- `lint.sh`
- `sim.sh`
- `synth.sh`
- `test.sh`

---

# پوشه synth/

این پوشه خروجی‌های حاصل از فرآیند سنتز طراحی VHDL را نگهداری می‌کند.

نمونه فایل‌ها:

```text
system_top.v
system_top.dot
system_top.raw.vhdl
system_top.netlist.vhdl
system_top_opt.v
system_top.json
system_top.blif
system_top.edif
system_top.rtlil
```

بسته به تنظیمات سنتز، ممکن است فایل‌های دیگری نیز تولید شوند.

کاربرد فایل‌های متداول:

| فایل | توضیح |
|------|-------|
| system_top.v | نت‌لیست Verilog تولیدشده توسط GHDL |
| system_top.raw.vhdl | خروجی خام VHDL پس از سنتز |
| system_top.netlist.vhdl | نت‌لیست VHDL بهینه‌شده |
| system_top.dot | نمایش گرافیکی مدار در قالب Graphviz |
| system_top.json | نت‌لیست در قالب JSON برای ابزارهای دیگر |
| system_top.blif | نت‌لیست در قالب BLIF |
| system_top.edif | نت‌لیست در قالب EDIF |
| system_top.rtlil | نمایش میانی RTLIL مورد استفاده Yosys |
| system_top_opt.v | نت‌لیست Verilog بهینه‌شده توسط Yosys |

این فایل‌ها عمدتاً برای سنتز، تحلیل طراحی، مشاهده ساختار مدار و استفاده در جریان‌های طراحی FPGA و ASIC کاربرد دارند.

توسط دستور زیر تولید می‌شوند:

```bash
make synth
```

یا

```bash
./scripts/synth.sh
```

---

# پوشه waves/

این پوشه فایل‌های شکل موج حاصل از شبیه‌سازی را نگهداری می‌کند.

نمونه فایل‌ها:

```text
cpu.ghw
```

یا

```text
cpu.vcd
```

این فایل‌ها را می‌توان با ابزارهایی مانند GTKWave مشاهده و تحلیل کرد.

توسط دستور زیر تولید می‌شوند:

```bash
make sim
```

---

# پوشه work/

این پوشه شامل فایل‌های موقت ایجادشده توسط GHDL است.

نمونه:

```text
work-obj08.cf
```

این فایل‌ها کتابخانه‌های کامپایل‌شده VHDL را نگهداری می‌کنند و در صورت حذف، هنگام اجرای مجدد پروژه به‌طور خودکار دوباره ساخته می‌شوند.

به‌طور معمول نیازی به ویرایش این پوشه وجود ندارد.

---

# پاک‌سازی فایل‌های تولیدشده

برای حذف تمام فایل‌های تولیدشده از دستور زیر استفاده کنید:

```bash
make clean
```

یا

```bash
./scripts/clean.sh
```

اسکریپت پاک‌سازی تمامی فایل‌های تولیدشده را حذف کرده و فایل‌های اصلی پروژه را بدون تغییر باقی می‌گذارد.

---

# نکات

- تمام محتوای پوشه `build/` به‌صورت خودکار تولید می‌شود.
- هیچ فایل منبع (Source File) در این پوشه قرار ندارد.
- فایل‌ها در هر بار اجرای اسکریپت‌های مربوطه مجدداً تولید می‌شوند.
- فایل‌های گزارش دارای برچسب زمانی (Timestamp) هستند تا سوابق اجراهای قبلی حفظ شوند.
