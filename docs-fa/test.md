# چارچوب تست

## معرفی

پروژه **RISC-4 Educational CPU** دارای یک چارچوب تست خودکار برای اعتبارسنجی تمامی دستورالعمل‌های پشتیبانی‌شده و بررسی عملکرد کامل پردازنده است.

فرآیند تست به صورت کاملاً خودکار انجام می‌شود و شامل مراحل زیر است:

1. تحلیل فایل‌های VHDL
2. اسمبل برنامه‌های اسمبلی
3. شبیه‌سازی پردازنده
4. استخراج نتایج
5. مقایسه خروجی با نتیجه مورد انتظار
6. تولید گزارش نهایی تست‌ها

برای اجرای کل فرآیند تنها کافی است یکی از دستورات زیر را اجرا کنید:

```bash
make test
```

یا

```bash
./scripts/test.sh
```

---

# ساختار پوشه تست‌ها

تمام فایل‌های مربوط به تست در پوشه `tb/` قرار دارند.

```text
tb/
├── integration/
│   └── tb_cpu.vhdl
│
├── unit/
│   ├── tb_alu.vhdl
│   ├── tb_control.vhdl
│   ├── tb_ir.vhdl
│   ├── tb_pc.vhdl
│   ├── tb_register_file.vhdl
│   └── ...
│
└── programs/
    ├── test.lst
    ├── program_test.mem
    ├── asm/
    ├── bin/
    ├── out/
    └── exp/
```

---

# تست‌های واحد (Unit Tests)

پوشه `unit/` شامل تست‌بنچ‌های مستقل برای هر یک از ماژول‌های سخت‌افزاری است.

در حال حاضر تست‌های زیر در پروژه وجود دارند:

| فایل | ماژول |
|------|--------|
| tb_alu.vhdl | واحد محاسبات و منطق (ALU) |
| tb_control.vhdl | ماشین حالت کنترل (Control FSM) |
| tb_ir.vhdl | ثبات دستورالعمل (Instruction Register) |
| tb_pc.vhdl | شمارنده برنامه (Program Counter) |
| tb_register_file.vhdl | فایل ثبات‌ها (Register File) |
| ... | ... |

هر تست‌بنچ فقط عملکرد یک ماژول را به صورت مستقل بررسی می‌کند.

---

# تست یکپارچه (Integration Test)

تست یکپارچه کل پردازنده را اجرا می‌کند.

```text
tb/integration/tb_cpu.vhdl
```

این تست‌بنچ برنامه اسمبلی اسمبل‌شده را داخل حافظه دستورالعمل بارگذاری کرده و پردازنده را تا اجرای دستور `HALT` اجرا می‌کند.

پس از پایان اجرا، وضعیت نهایی پردازنده گزارش می‌شود که شامل موارد زیر است:

- مقدار شمارنده برنامه (PC)
- مقدار ثبات‌ها
- وضعیت پرچم‌ها (Flags)
- وضعیت توقف پردازنده (HALT)

---

# برنامه‌های تست

برای هر دستور پردازنده، یک برنامه تست مستقل در نظر گرفته شده است.

محل قرارگیری این فایل‌ها:

```text
tb/programs/asm/
```

نمونه فایل‌ها:

```text
add.asm
sub.asm
movi.asm
jump.asm
jz.asm
jc.asm
...
```

تا حد امکان هر برنامه تنها یک قابلیت یا دستور خاص از پردازنده را آزمایش می‌کند.

---

# فایل‌های اسمبلی (.asm)

این فایل‌ها برنامه‌هایی هستند که توسط پردازنده اجرا می‌شوند.

نمونه:

```asm
MOVI R0,5
MOVI R1,2
ADD R2,R0,R1
HALT
```

این فایل‌ها توسط اسمبلر پروژه به کد ماشین تبدیل می‌شوند.

---

# فایل‌های کد ماشین (.mem)

این فایل‌ها توسط اسکریپت زیر تولید می‌شوند:

```text
assembler.sh
```

و در مسیر زیر قرار می‌گیرند:

```text
tb/programs/bin/
```

نمونه:

```text
1805
1902
0250
8800
```

این فایل‌ها مستقیماً توسط حافظه دستورالعمل در زمان شبیه‌سازی بارگذاری می‌شوند.

---

# فایل‌های خروجی مورد انتظار (.exp)

این فایل‌ها وضعیت صحیح پردازنده پس از پایان اجرای برنامه را مشخص می‌کنند.

محل قرارگیری:

```text
tb/programs/exp/
```

نمونه:

```text
HALTED=1
PC=4
REG[0]=5
REG[1]=2
REG[2]=7
REG[3]=0
FLAG[ZERO]=0
FLAG[CARRY]=0
```

در واقع این فایل‌ها وضعیت معماری صحیح پردازنده را مشخص می‌کنند و مبنای مقایسه نتایج شبیه‌سازی هستند.

---

# فایل‌های خروجی شبیه‌سازی (.out)

این فایل‌ها هنگام اجرای تست‌ها به صورت خودکار تولید می‌شوند.

محل قرارگیری:

```text
tb/programs/out
```

نمونه:

```text
HALTED=1
PC=4
REG[0]=5
REG[1]=2
REG[2]=7
REG[3]=0
FLAG[ZERO]=0
FLAG[CARRY]=0
```

این فایل‌ها وضعیت واقعی پردازنده پس از پایان شبیه‌سازی را نشان می‌دهند.

---

# فایل فهرست تست‌ها (test.lst)

فایل `test.lst` لیست تمام برنامه‌های تست پروژه را نگهداری می‌کند.

هر خط از این فایل نام یک تست را مشخص می‌کند.

نمونه:

```text
movi
add
sub
load
store
jump
jz
jc
```

اسکریپت `test.sh` این فایل را می‌خواند و تمام تست‌های موجود را به ترتیب اجرا می‌کند.

برای اضافه کردن یک تست جدید، کافی است نام آن را به این فایل اضافه کنید.

---

# نحوه مقایسه خروجی‌ها

برای هر تست، مراحل زیر انجام می‌شود:

```text
.asm
   │
   ▼
assembler.awk
   │
   ▼
.mem
   │
   ▼
Instruction Memory
   │
   ▼
CPU Simulation
   │
   ▼
.out
   │
   ▼
diff
   │
   ▼
PASS / FAIL
```

فایل `.out` تولیدشده با فایل `.exp` متناظر مقایسه می‌شود.

در صورتی که هر دو فایل کاملاً یکسان باشند:

```text
PASS
```

در غیر این صورت:

```text
FAIL
```

و اختلاف دقیق دو فایل نمایش داده می‌شود.

# روند اجرای تست‌ها

فرآیند کامل تست به صورت زیر است:

```text
lint.sh
      │
      ▼
assembler.sh
      │
      ▼
کامپایل Testbench
      │
      ▼
بارگذاری فایل .mem
      │
      ▼
اجرای پردازنده
      │
      ▼
تولید فایل .out
      │
      ▼
مقایسه با فایل .exp
      │
      ▼
PASS / FAIL
```

# اضافه کردن یک تست جدید

برای افزودن تست یک دستور جدید کافی است:

1. فایل اسمبلی را ایجاد کنید.

```text
tb/programs/asm/new_instruction.asm
```

2. خروجی مورد انتظار را تعریف کنید.

```text
tb/programs/exp/new_instruction.exp
```

3. نام تست را به فایل زیر اضافه کنید.

```text
tb/programs/tests.lst
```

4. تست‌ها را اجرا کنید.

```bash
make test
```

چارچوب تست به صورت خودکار:

- برنامه را اسمبل می‌کند.
- شبیه‌سازی را اجرا می‌کند.
- خروجی را با نتیجه مورد انتظار مقایسه می‌کند.
- نتیجه تست را در گزارش نهایی نمایش می‌دهد.

در حالت عادی نیازی به تغییر اسکریپت `test.sh` وجود ندارد.

# نکات

- برای هر دستور پردازنده بهتر است حداقل یک تست مستقل وجود داشته باشد.
- هر تست تا حد امکان فقط یک قابلیت را بررسی کند.
- خروجی مورد انتظار باید کاملاً قطعی و قابل تکرار باشد.
- تمام فایل‌های تولیدشده هنگام اجرای تست‌ها در پوشه `tb/programs/out` ذخیره می‌شوند.
- تست‌های واحد، هر ماژول را به صورت مستقل بررسی می‌کنند، در حالی که تست یکپارچه عملکرد کل پردازنده را ارزیابی می‌کند.
